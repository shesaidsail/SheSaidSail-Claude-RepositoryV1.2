## SECTION 1 — UNIVERSAL FIELD STANDARDS

Every Make scenario that writes to Airtable must include these fields on every CREATE operation. These are non-negotiable. Any CREATE that omits a Universal field is a governance violation.

| Field Name | Airtable Type | Source | Value Logic | Required on CREATE |
|-----------|--------------|--------|------------|-------------------|
| `Environment` | Single Select | Make scenario variable | `Sandbox` during sandbox testing; `Production` only after Founder-approved production activation | REQUIRED — ALWAYS |
| `Brand` | Single Select | M-BRAND-ROUTER classification output | `SSS` or `ME` — never null on any record | REQUIRED — ALWAYS |
| `Source_System` | Single Select | Static (set by Make) | Always `Make` for any record created by a Make scenario | REQUIRED — ALWAYS |
| `Created_At` | DateTime | Make `{{now}}` | UTC timestamp at moment of record creation | REQUIRED — ALWAYS |
| `Updated_At` | DateTime | Make `{{now}}` | UTC timestamp — set on CREATE; updated on every subsequent UPDATE to this record | REQUIRED — ALWAYS |
| `City` | Single Select | Webhook payload or inherited from Request | Must match an approved City value — see Section 10 | REQUIRED when city context is known; OPTIONAL on early-stage intake if client has not specified |

**Universal Fields on UPDATE Operations:**
Every Make UPDATE operation must write `Updated_At = {{now}}`. No other Universal fields are updated by Make — they are set once on CREATE and are thereafter immutable except by Will.

### 2.2 — M-LEAD-INTAKE Field Write Sequence

Make writes fields in this sequence within the Airtable CREATE module to minimize formula dependency conflicts:

```
Step 1: Write all Universal fields (Environment, Brand, Source_System, Created_At, Updated_At)
Step 2: Write all payload-sourced fields (Name, Email, Phone, Charter_Date, Group_Size, etc.)
Step 3: Write M-BRAND-ROUTER output fields (Brand, Brand_Confidence_Score)
Step 4: Write Status and Agent_Status based on classification result
Step 5: Write Webhook_Payload_Raw (last — ensures all other fields written before raw log)
```

## SECTION 8 — FIELD VALIDATION RULES

### 8.1 — Type Constraints by Airtable Field Type

| Airtable Field Type | Make Input Format | Validation Rule | Rejection Action |

| Single Line Text | String | Max 500 characters. No HTML. No scripts. | Truncate to 500 chars and log anomaly if exceeded. |
| Long Text | String | No limit enforced by Make. Airtable max 100,000 chars. | If > 100,000 chars: truncate and log anomaly. |

| Number | Numeric | No leading zeros unless decimal. No currency symbols. Strip commas. | Strip formatting. If still non-numeric: set to null and log. |

| Single Select | String | Must exactly match an approved enum value (case-insensitive compare; write with canonical casing). | If no match: write `Other` if field has that option; else set null and log anomaly. |

## SECTION 9 — PROTECTED FIELDS — MAKE MUST NEVER OVERWRITE

These fields are immutable once set, or are governed by rules that prohibit Make writes after a threshold condition is met. Any Make module that attempts to write these fields after the threshold must be considered a bug and treated as a critical error.

### 9.1 — Absolutely Immutable Fields (Never Written by Make After Initial Set)

| Field | Table | Who Sets It | Why Protected |
|-------|-------|------------|--------------|
| `Booking_ID` | Bookings | Airtable formula (auto) | Human-readable ID — immutable identity |
| `Request_ID` | Requests | Airtable formula (auto) | Human-readable ID — immutable identity |
| `Log_ID` | Audit Log | Airtable formula (auto) | Audit record identity — immutable |
| `Created_At` | All tables | Make (on CREATE) | Creation timestamp — never update |
| `UUID` / `RECORD_ID()` | All tables | Airtable (auto) | System identity — never manually set |
| `Stripe_Payment_Intent_ID` | Bookings | M-STRIPE-DEPOSIT (once) | Stripe financial record — immutable after creation |
| `Stripe_Payment_Link_ID` | Bookings | M-STRIPE-DEPOSIT (once) | Stripe financial record — immutable after creation |
| `Submission_Timestamp` | Requests | M-LEAD-INTAKE (once) | Original form submission time — audit baseline |

### 9.2 — Conditionally Protected Fields (Make Must Not Write After Threshold)

| Field | Table | Threshold Condition | Why Protected After Threshold |
|-------|-------|--------------------|----|
| `Package_Price` | Bookings | Status = CONFIRMED | Financial lock — price change after confirmation is a financial integrity violation |
| `Deposit_Amount` | Bookings | `Stripe_Payment_Intent_ID` is populated | Changing deposit after Stripe link is created without voiding the Stripe link first is a financial error |
| `Confirmation_Sent` | Bookings | Set to `true` | Idempotency gate — re-setting to `false` would re-enable re-send of confirmation |
| `Status` on Bookings | Bookings | Status = CONFIRMED or later | Status may only progress forward through the lifecycle. Make may not revert a CONFIRMED booking to NEW or earlier state. |
| `Agent_Status` | Requests | `HUMAN_REVIEW` | Make must never downgrade from HUMAN_REVIEW to AI_RESPONDING. Only Luciana or Will may clear HUMAN_REVIEW state. |
| `Emergency_Flag` | Bookings | When set to `true` by Will or Luciana | Make must never set Emergency_Flag = false autonomously. Only Will may clear it. |
| `Chargeback_Risk` | Bookings | Any value | Make never writes Chargeback_Risk. This field is Luciana/Will only. |
| `Charter_Notes` | Bookings | — | Append-only field. Make may append text but must never overwrite existing content. Use Airtable formula for append or Make text concatenation. |
| `Net_Margin_Pct` | Bookings | — | Formula field — Make must never attempt to write formula fields |
| `D7_Review_Eligible` | Bookings | — | Formula field — Make must never attempt to write formula fields |

### 9.3 — Audit Log Immutability

The Audit Log table (tblrMpTfMk8q1eNHp) has a special protection regime:

| Operation | Permitted | Who May Execute |
|-----------|----------|----------------|
| CREATE new record | YES | M-AUDIT-LOGGER (Make) |
| UPDATE existing record | NO (except Approval_State) | Prohibited for Make. `Approval_State` may be set to `VOIDED` by Will only via Airtable UI. |
| DELETE any record | NEVER | Prohibited for all parties including Will. Archive instead. |

The Make API token scoped to M-AUDIT-LOGGER must have CREATE-ONLY permission on the Audit Log table. If this token is found to have UPDATE or DELETE permissions, that is a security misconfiguration and must be corrected immediately.

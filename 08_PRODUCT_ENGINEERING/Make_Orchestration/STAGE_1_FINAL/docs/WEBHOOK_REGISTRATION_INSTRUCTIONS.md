## 1. WEBFLOW FORM SUBMISSION WEBHOOK

**Target scenario:** M-LEAD-INTAKE  
**Trigger:** Every form submission on She Said Sail and Mare Executive sites  

### Registration Steps

1. In Make, open M-LEAD-INTAKE
2. Click the webhook module (Module 1 — gateway:CustomWebHook)
3. Copy the webhook URL displayed (format: `https://hook.us1.make.com/XXXX`)
4. Go to Webflow: **Dashboard > Site Settings > Integrations > Webhooks**
5. Click **Add Webhook**
6. Select trigger type: **Form Submission**
7. Paste the Make webhook URL
8. Click Save
9. Test by submitting the inquiry form on shesaidsail.com
10. Verify Make scenario shows an execution in history

**Repeat for Mare Executive site** if it has a separate Webflow project.

### Webflow Payload Format

Make expects the Webflow form submission body to include:
- `name` — client full name
- `email` — client email address
- `phone` — client phone (optional)
- `occasion` — event type (bachelorette, birthday, etc.)
- `preferred_date` — requested charter date
- `guest_count` — number of guests
- `budget` — budget range (optional)
- `message` — additional notes
- `source` — form source URL (Webflow auto-populates or set as hidden field)
- `brand` — optional hidden field set to "sss" or "mare" based on site

**Add a hidden field** named `brand` in each Webflow form with a default value of `sss` for She Said Sail forms and `mare` for Mare Executive forms. This ensures M-BRAND-ROUTER classifies correctly without relying solely on URL pattern matching.

## 2. STRIPE DEPOSIT WEBHOOK

**Target scenario:** M-BOOKING-CREATION  
**Trigger:** When a client completes the deposit payment via Stripe Payment Link  

### Registration Steps

1. In Make, open M-BOOKING-CREATION
2. Click the webhook module (Module 1 — gateway:CustomWebHook)
3. Copy the webhook URL
4. Go to Stripe Dashboard: **Developers > Webhooks > Add endpoint**
5. Paste the Make webhook URL in the "Endpoint URL" field
6. Under "Events to listen to," select: **`checkout.session.completed`**
7. Click **Add endpoint**
8. After creation, click the endpoint to reveal the **Signing secret**
9. Copy the signing secret
10. Store it as `STRIPE_WEBHOOK_SIGNING_SECRET` in Make credential vault
11. Also store it in your secure credential store (1Password, etc.)

### Test the Stripe Webhook

1. In the Stripe webhook endpoint settings, click **Send test event**
2. Select `checkout.session.completed`
3. Click **Send test event**
4. Verify Make scenario shows execution in history
5. Verify Booking record is not updated (test events have no real metadata — expected behavior)

### Production Validation

When a real client completes deposit payment:
1. Make scenario receives the webhook within 30 seconds
2. Booking status updates from DEPOSIT_SENT to DEPOSIT_PAID
3. Slack notification appears in #sss-ops-alerts
4. Audit Log record created

**Note:** This webhook is for the balance payment scenario (CHARTER-002 — M-BALANCE-RECEIVED), which is a Stage 2 scenario not included in Stage 1. Pre-register now to avoid delays when Stage 2 deploys.

## INTERNAL WEBHOOK ENDPOINTS (NO EXTERNAL REGISTRATION REQUIRED)

These endpoints are Make-to-Make and are called internally by operational scenarios. They are already configured inside the blueprints via `{{VARIABLE}}` tokens that get bound to the actual URLs after import.

| Endpoint Variable | Generated By | Called By |
|------------------|-------------|----------|
| `AUDIT_LOGGER_WEBHOOK_URL` | M-AUDIT-LOGGER import | M-LEAD-INTAKE, M-STRIPE-DEPOSIT, M-BOOKING-CREATION, M-CONCIERGE-ASSIGNMENT, M-BOOKING-CONFIRMATION |
| `SLACK_ALERTS_WEBHOOK_URL` | M-SLACK-ALERTS import | M-LEAD-INTAKE, M-BOOKING-CREATION |
| `BRAND_ROUTER_WEBHOOK_URL` | M-BRAND-ROUTER import | M-LEAD-INTAKE |

After importing each infrastructure scenario, copy its webhook URL and add it to Make's credential vault under the variable name listed above.

---

## WEBHOOK SECURITY NOTES

All Make webhook endpoints generate a unique URL that acts as a secret. Additionally:

- The `Authorization: Bearer {{SECRET}}` header is used between internal scenarios — set and store secrets per the credential checklist.
- For Stripe webhooks, always validate the `Stripe-Signature` header. The `STRIPE_WEBHOOK_SIGNING_SECRET` is required for this. (See gap noted in `Make_Native_Module_Gap_Audit.md` — signature validation requires additional implementation.)
- Webhook URLs should not be shared publicly or committed to version control.
- If a webhook URL is compromised, regenerate it in Make and update all callers.

## Quick Start

1. Read `MAKE_IMPORT_INSTRUCTIONS.md` completely before starting
2. Import blueprints in this exact order:
   1. M-AUDIT-LOGGER
   2. M-SLACK-ALERTS
   3. M-BRAND-ROUTER
   4. M-LEAD-INTAKE
   5. M-CONCIERGE-ASSIGNMENT
   6. M-STRIPE-DEPOSIT
   7. M-BOOKING-CONFIRMATION
   8. M-BOOKING-CREATION
3. After each import: reconnect credentials and update webhook URLs
4. Run sandbox tests using `SANDBOX_TEST_SEQUENCE.md`
5. Activate production using `PRODUCTION_ENABLE_ORDER.md`

## What These 8 Scenarios Do

| Scenario | What It Does |
|----------|-------------|
| **M-AUDIT-LOGGER** | Receives audit events from all other scenarios. Writes immutable records to Airtable Audit Log. The backbone of all automation governance. |
| **M-BRAND-ROUTER** | Routes inbound events to brand-specific processing (SSS vs ME). Sets brand context variables before passing to M-LEAD-INTAKE. |
| **M-LEAD-INTAKE** | Receives enriched lead data. Creates or updates a Request record in Airtable. Triggers Slack alert and audit log entry. |
| **M-SLACK-ALERTS** | Centralized Slack notification hub. Routes alerts to correct channels based on alert type and urgency. |
| **M-CONCIERGE-ASSIGNMENT** | Finds the appropriate concierge for a confirmed availability request. Assigns them, notifies via email and Slack. |
| **M-STRIPE-DEPOSIT** | Creates a Stripe Payment Link for the deposit amount. Sends deposit request via email and SMS. Updates booking record. |
| **M-BOOKING-CREATION** | Triggered by Stripe payment success webhook. Creates or updates the Booking record in Airtable. Triggers confirmation. |
| **M-BOOKING-CONFIRMATION** | Sends branded booking confirmation email and SMS to client. Updates booking status. Notifies Slack. |

## Critical Limitations

1. **Credentials are NOT included.** All connections must be manually reconnected in Make after import.
2. **Webhook URLs are NOT pre-filled.** They are generated by Make after import and must be manually entered in HTTP modules.
3. **Airtable table IDs for new tables** (Automation_Health, Concierge_Operators) must be retrieved after those tables are created.
4. **Stripe webhook** must be registered manually in the Stripe Dashboard pointing to the M-BOOKING-CREATION URL.
5. **Do NOT activate in production** until all 16 sandbox tests pass.

---

## Architecture Notes

- All scenarios are webhook-triggered (instant, not scheduled)
- All scenarios call M-AUDIT-LOGGER as the final step before completion
- All scenarios call M-SLACK-ALERTS for operational notifications
- Idempotency is implemented in M-AUDIT-LOGGER and M-BOOKING-CREATION
- Error handling in each scenario routes to Slack (#sss-ops-alerts) on failure
- Brand context (SSS vs ME) is carried throughout the chain via payload fields
- Environment field ("production" vs "sandbox") is enforced to prevent test data from hitting production

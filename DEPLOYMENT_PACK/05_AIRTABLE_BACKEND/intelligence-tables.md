# She Said Sail: Intelligence Layer Airtable Tables
**Version:** 1.0
**Date:** May 2026
**Purpose:** Defines the six new Airtable tables that form the intelligence layer on top of the existing 7-table backend. Create these tables after the original 7 are stable. These tables extend the architecture without replacing anything.

---

## EXISTING TABLE MODIFICATIONS

Before creating the new tables, add these fields to existing tables:

### Requests Table: New Fields

| Field Name | Field Type | Notes |
|---|---|---|
| Source Type | Single Select | Options: Form Lead, Chatbot Lead, Contact Form, Manual. Set by Make.com on create. |
| Visitor ID | Short Text | From sss_vid cookie. Captured in form and chatbot payloads. Used for cross-system visitor linking. |
| Chatbot Conversation | Linked Record | Links to Chatbot Conversations table. Populated by M-CHATBOT-001. |
| Revenue Attribution | Linked Record | Links to Revenue Attribution table. Populated by M-BOOKING-OUTCOME-001. |

### Bookings Table: New Fields

| Field Name | Field Type | Notes |
|---|---|---|
| Charter Cost | Currency | Estimated cost of the charter (crew, boat, fuel, catering). Set manually or by Make. |
| Gross Margin | Formula | Total Value minus Charter Cost. Auto-calculated. |
| Margin Percent | Formula | Gross Margin divided by Total Value, formatted as percent. |
| Days to Close | Formula | Charter Date minus the linked Request's Submitted At. Shows booking lead time. |
| Request | Linked Record | Links to the originating Requests record. Required. |
| Revenue Attribution | Linked Record | Links to Revenue Attribution table. Populated by M-BOOKING-OUTCOME-001. |

### Campaigns Table: New Fields

| Field Name | Field Type | Notes |
|---|---|---|
| Total Revenue | Rollup | Sum of Revenue from linked Revenue Attribution records. |
| Total Bookings | Rollup | Count of Revenue Attribution records linked to this Campaign. |
| ROI Percent | Formula | (Total Revenue minus Budget) divided by Budget, formatted as percent. Requires Budget field already present. |
| Cost Per Booking | Formula | Budget divided by Total Bookings. |

## NEW TABLE 1: Chatbot Conversations

**Primary Field:** Conversation ID (Auto Number)
**Purpose:** Stores the full conversation path and outcome for every chatbot session that reaches STATE_HANDOFF. Complements the Requests table entry (which stores the lead data) with conversation intelligence.
**Create after:** Requests table is stable and M-CHATBOT-001 is live.

| Field Name | Field Type | Notes |
|---|---|---|
| Conversation ID | Auto Number | Primary field. |
| Request | Linked Record | Links to the Requests record created by M-CHATBOT-001. One-to-one. |
| Visitor ID | Short Text | From sss_vid cookie in chatbot payload. Links to UTMs table visitor_id. |
| Session ID | Short Text | From sessionStorage. Unique per page session. |
| Started At | Date/Time | When the chatbot widget was opened. From chatbot_open GTM event timestamp. |
| Completed At | Date/Time | When the handoff message was shown (STATE_HANDOFF). |
| Duration Seconds | Number | Completed At minus Started At in seconds. |
| Occasion | Single Select | Options: bachelorette, birthday, girls_trip, intimate, other. |
| Occasion Energy | Single Select | Options: high, elevated, relaxed, intimate. |
| Guest Count | Short Text | Range string from chatbot (e.g., "9 to 15"). |
| Experience Recommended | Single Select | Options: Monaco Social, Golden Hour Escape, Rose Day Club, Pink Palm Club. |
| Experience Confirmed | Checkbox | True if user clicked "Yes, that sounds right" at recommendation step. |
| States Visited | Long Text | JSON array of state IDs visited during the conversation (e.g., ["opener","occasion","energy","recommendation","date","name","email","handoff"]). Populated by chatbot JS. |
| Questions Asked Count | Number | Total number of bot messages displayed to the user. |
| Email Captured | Checkbox | True if valid email was submitted. |
| Phone Captured | Checkbox | True if phone number was submitted. |
| Escalation Requested | Checkbox | True if user triggered escalation flow. |
| Dead End Hit | Checkbox | True if unrecognized input handler fired during conversation. |
| Silence Trigger | Checkbox | True if the 90-second silence handler fired. |
| Conversation Summary | Long Text | Auto-generated by chatbot JS: occasion + experience + guest count + date as a summary string. |
| Landing Page | URL | Window location at time of chatbot open. |
| UTM Source | Short Text | From sessionStorage sss_utm at handoff time. |
| UTM Campaign | Short Text | From sessionStorage sss_utm at handoff time. |
| UTM Content | Short Text | Creative ID from sss_utm at handoff time. |
| Trigger Type | Single Select | Options: manual, auto. Whether user opened manually or it was auto-triggered. |
| Outcome | Single Select | Options: Handoff Completed, Escalation, Abandoned, Error. |

### Views Required

| View Name | Filter | Sort |
|---|---|---|
| This Week | Started At is within this week | Started At: descending |
| Completed Handoffs | Outcome = Handoff Completed | Started At: descending |
| Escalations | Escalation Requested = true | Started At: descending |
| All Conversations | None | Started At: descending |

## NEW TABLE 2: Revenue Attribution

**Primary Field:** Attribution ID (Auto Number)
**Purpose:** The central intelligence record that closes the loop from marketing source to booking revenue. One record per confirmed booking. Created by M-BOOKING-OUTCOME-001.
**Create after:** Bookings and UTMs tables are stable.

| Field Name | Field Type | Notes |
|---|---|---|
| Attribution ID | Auto Number | Primary field. |
| Booking | Linked Record | The confirmed Booking record. Required. One-to-one. |
| Request | Linked Record | The originating Request record. Lookup via Booking. |
| UTM Record | Linked Record | The UTM record linked to the originating Request. |
| Campaign | Linked Record | The Campaign record matched by utm_campaign slug. |
| Experience | Short Text | Lookup from Booking.Experience. |
| Revenue | Currency | Lookup from Booking.Total Value. |
| Charter Cost | Currency | Lookup from Booking.Charter Cost. |
| Gross Margin | Formula | Revenue minus Charter Cost. |
| Margin Percent | Formula | Gross Margin divided by Revenue, as percent. |
| UTM Source | Short Text | Lookup from UTM Record. |
| UTM Medium | Short Text | Lookup from UTM Record. |
| UTM Campaign | Short Text | Lookup from UTM Record. |
| UTM Content | Short Text | Lookup from UTM Record (creative ID). |
| Creative ID | Short Text | Lookup from UTM Record. |
| Landing Page | URL | Lookup from UTM Record. |
| First Seen At | Date/Time | Lookup from UTM Record. The visitor's first arrival. |
| Request Submitted At | Date/Time | Lookup from Request.Submitted At. |
| Booking Confirmed At | Date/Time | Lookup from Booking.Deposit Date. |
| Days First Visit to Request | Number | Request Submitted At minus First Seen At in days. |
| Days Request to Booking | Number | Booking Confirmed At minus Request Submitted At in days. |
| Days Total | Number | Booking Confirmed At minus First Seen At in days. Full cycle time. |
| Source Type | Short Text | Lookup from Request.Source Type (Form Lead, Chatbot Lead, etc.). |
| Notes | Long Text | Any manual notes about this attribution. |

### Views Required

| View Name | Filter | Sort |
|---|---|---|
| This Month | Booking Confirmed At is within this month | Revenue: descending |
| By Source | None | UTM Source: ascending |
| By Campaign | None | UTM Campaign: ascending |
| All Attribution | None | Booking Confirmed At: descending |
| High Margin | Margin Percent > 50 | Margin Percent: descending |

## NEW TABLE 3: Experience Performance

**Primary Field:** Record Name (Formula: Experience & " - " & Week)
**Purpose:** Weekly snapshot of performance metrics per experience. Updated every Monday by M-EXPERIENCE-ROLLUP-001. Allows trending over time.
**Create after:** Requests and Bookings tables are stable.

| Field Name | Field Type | Notes |
|---|---|---|
| Record Name | Formula | Concatenation of Experience and Week (e.g., "Monaco Social - Week 20 2026"). |
| Experience | Single Select | Options: Monaco Social, Golden Hour Escape, Rose Day Club, Pink Palm Club. |
| Week | Short Text | ISO week string (e.g., "2026-W20"). Set by Make.com rollup scenario. |
| Period Start | Date | Monday of the week. |
| Period End | Date | Sunday of the week. |
| Requests This Week | Number | Count of Requests where Experience Interest contains this experience and Submitted At is within the week. |
| Bookings This Week | Number | Count of Bookings where Experience = this experience and Deposit Date is within the week. |
| Close Rate | Formula | Bookings This Week divided by Requests This Week, formatted as percent. Shows only when both > 0. |
| Revenue This Week | Currency | Sum of Booking.Total Value for bookings this week for this experience. |
| Average Booking Value | Formula | Revenue This Week divided by Bookings This Week. |
| Average Margin | Currency | Average of Booking.Gross Margin for bookings this week for this experience. |
| Chatbot Leads This Week | Number | Count of Requests with Source Type = "Chatbot Lead" and Experience Interest containing this experience. |
| Chatbot Close Rate | Formula | Bookings from chatbot leads divided by chatbot leads, as percent. |
| Hot Leads This Week | Number | Count of Requests with Internal Rating = Hot and this experience. |
| Notes | Long Text | Manual notes for unusual patterns in this week's data. |

### Views Required

| View Name | Filter | Sort |
|---|---|---|
| Current Week | Week = current ISO week | Experience: ascending |
| Monaco Social History | Experience = Monaco Social | Period Start: descending |
| Golden Hour History | Experience = Golden Hour Escape | Period Start: descending |
| Rose Day Club History | Experience = Rose Day Club | Period Start: descending |
| Pink Palm Club History | Experience = Pink Palm Club | Period Start: descending |
| All Records | None | Period Start: descending |

## NEW TABLE 4: Weekly Insights

**Primary Field:** Week (Short Text, e.g., "2026-W20")
**Purpose:** Stores the output of each weekly AI analysis run. The accumulating record of intelligence over time.
**Create after:** M-WEEKLY-REPORT-001 is live and tested.

| Field Name | Field Type | Notes |
|---|---|---|
| Week | Short Text | Primary field. ISO week (e.g., "2026-W20"). |
| Period Start | Date | Monday of the week. |
| Period End | Date | Sunday of the week. |
| Total Requests | Number | Count of requests created this week. |
| Bachelorette Requests | Number | Requests where Occasion = Bachelorette. |
| Birthday Requests | Number | Requests where Occasion = Birthday. |
| Girls Trip Requests | Number | Requests where Occasion = Girls Trip. |
| Total Bookings | Number | Count of bookings confirmed this week. |
| Total Revenue | Currency | Sum of revenue booked this week. |
| Conversion Rate | Formula | Total Bookings divided by Total Requests, as percent. |
| Chatbot Conversations | Number | Total chatbot conversations this week. |
| Chatbot Handoffs | Number | Conversations that reached handoff. |
| Chatbot Completion Rate | Formula | Chatbot Handoffs divided by Chatbot Conversations, as percent. |
| Top Traffic Source | Short Text | UTM source with highest request count this week. |
| Top Campaign | Short Text | UTM campaign with highest request count this week. |
| Hot Leads Count | Number | Requests rated Hot this week. |
| Closed Lost Count | Number | Requests moved to Closed Lost this week. |
| Average Days to Close | Number | Average Days Total from Revenue Attribution records this week. |
| AI Analysis | Long Text | The Claude-generated narrative analysis for this week. May be empty if API not connected. |
| Recommendations | Long Text | Numbered list of recommendations from the AI analysis. |
| Founder Decisions | Linked Record | Any Founder Decisions created in response to this insight. |
| Status | Single Select | Options: Draft, Reviewed, Actions Taken. |

### Views Required

| View Name | Filter | Sort |
|---|---|---|
| Last 8 Weeks | Period Start >= 8 weeks ago | Period Start: descending |
| Reviewed | Status = Reviewed or Actions Taken | Period Start: descending |
| All Insights | None | Period Start: descending |

## NEW TABLE 5: Founder Decisions

**Primary Field:** Decision ID (Auto Number)
**Purpose:** Tracks every decision the founder makes in response to intelligence data. Closes the loop between analysis and outcome.
**Create after:** Weekly Insights table is live.

| Field Name | Field Type | Notes |
|---|---|---|
| Decision ID | Auto Number | Primary field. |
| Decision Date | Date | When the decision was made. |
| Category | Single Select | Options: Copy, Chatbot, Ad Creative, Concierge, Pricing, Funnel, Experience, Operations, Other. |
| Decision | Long Text | What was decided. Written in plain English. |
| Reason | Long Text | Why this decision was made. What data supported it. |
| Weekly Insight | Linked Record | Which Weekly Insights record prompted this decision. |
| Expected Outcome | Long Text | What the founder expects to happen as a result of this decision. |
| Measurement Plan | Long Text | How success will be measured and in what time frame. |
| Review Date | Date | When to check the outcome. Typically 4 weeks from Decision Date. |
| Actual Outcome | Long Text | What actually happened. Filled in on or after Review Date. |
| Lesson Linked | Linked Record | If a Lesson was documented from this outcome, link it here. |
| Status | Single Select | Options: Active, Under Review, Outcome Recorded, Abandoned. |

### Views Required

| View Name | Filter | Sort |
|---|---|---|
| Active Decisions | Status = Active | Decision Date: descending |
| Due for Review | Review Date <= today AND Status = Active | Review Date: ascending |
| Completed | Status = Outcome Recorded | Decision Date: descending |
| All Decisions | None | Decision Date: descending |

## NEW TABLE 6: Lessons Learned

**Primary Field:** Lesson ID (Auto Number)
**Purpose:** The knowledge base. Every significant finding, success, failure, and insight is documented here. The compound intelligence advantage of the business over time.
**Create after:** First month of Weekly Insights and Founder Decisions are recorded.

| Field Name | Field Type | Notes |
|---|---|---|
| Lesson ID | Auto Number | Primary field. |
| Lesson Date | Date | When the lesson was captured. |
| Category | Single Select | Options: Copy, Chatbot, Ad Creative, Concierge, Pricing, Funnel, Experience, Operations, SEO, Other. |
| Title | Short Text | One-sentence summary. e.g., "Bachelorette chatbot path converts at 2x the girls-trip path." |
| What Worked | Long Text | Specific description of what performed well. Include numbers. |
| What Did Not Work | Long Text | Specific description of what underperformed. Include numbers. |
| Why | Long Text | The suspected or confirmed reason for the outcome. |
| Impact | Single Select | Options: High, Medium, Low. |
| Evidence | Long Text | The data or observation that supports the lesson. |
| Related Decision | Linked Record | The Founder Decision this lesson came from. |
| Action Taken | Long Text | What change was made based on this lesson. |
| Result of Action | Long Text | The outcome of the action, measured 4 weeks later. |
| Tags | Multiple Select | Options: seasonal, pricing, copy, funnel, chatbot, ads, experience, concierge, mobile, repeat-booking. |
| Verified | Checkbox | True when the result has been confirmed by data. |

### Views Required

| View Name | Filter | Sort |
|---|---|---|
| High Impact | Impact = High | Lesson Date: descending |
| By Category | None | Category: ascending |
| Verified Lessons | Verified = true | Impact: descending |
| All Lessons | None | Lesson Date: descending |
| Chatbot Lessons | Tags contains chatbot | Lesson Date: descending |
| Ad Lessons | Tags contains ads | Lesson Date: descending |

## INTELLIGENCE TABLE BUILD ORDER

Build in this order to respect linked record dependencies:

1. Chatbot Conversations (links to Requests - already exists)
2. Revenue Attribution (links to Bookings, Requests, UTMs, Campaigns - all already exist)
3. Experience Performance (aggregation, no hard linked record dependencies)
4. Weekly Insights (links to Founder Decisions - build before #5)
5. Founder Decisions (links to Weekly Insights and Lessons Learned)
6. Lessons Learned (links to Founder Decisions)

Add new fields to existing Requests and Bookings tables after the new tables are created so linked record fields can point to them.

---

## AIRTABLE API SCOPE UPDATE

The Airtable Personal Access Token used by Make.com must have write access to the new tables.
When creating the new tables, verify the token has `data.records:write` on the new tables.
No new base permissions are needed. Same base, new tables.

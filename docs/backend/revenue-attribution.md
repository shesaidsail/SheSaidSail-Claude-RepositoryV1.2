# She Said Sail: Revenue Attribution System

Version: 1.0
Date: 2026-05-18

---

## PURPOSE

The revenue attribution system closes the loop between marketing spend and booking revenue. Every dollar of confirmed booking revenue gets traced back to its originating traffic source, campaign, and creative.

Without this system, She Said Sail can see how much money was booked in a given week, and it can see which campaigns generated leads in a given week. What it cannot do is connect those two facts. A $14,000 Monaco Social booking is invisible to the Campaigns table. The campaign that produced the lead has no record of the revenue it generated. ROI calculation is impossible.

This document describes the new Revenue Attribution table, the Make scenario that populates it, and the reporting outputs that depend on it.

---

## THE ATTRIBUTION GAP

### Current State

The UTMs table stores: Source, Medium, Campaign, Content, Term, First_Seen_At, and a linked Request record for every form submission or chatbot completion.

The Campaigns table stores: campaign name, UTM slug, budget, and a rollup of linked UTM records (lead count).

The Bookings table stores: Charter Date, Experience, Group Size, Total Value, and Deposit Date for every confirmed booking.

### The Missing Link

There is no field in Bookings that references a Request record. There is no field in Bookings that references a UTM record. There is no field in Bookings that references a Campaign record.

The Requests table has a Status field. When a lead converts, the Status is updated to "Booked." However, this status change does not trigger any Make.com scenario that creates or updates a Booking record, and it does not write any attribution data.

The result: the Campaigns table shows that the bachelorette-meta-may2026 campaign generated 23 leads. The Bookings table shows that $84,000 in revenue was booked last month. These two facts exist in isolation. The system cannot tell the founder how much of that $84,000 came from Meta, how much came from organic search, or how much came from Instagram.

### Why This Matters

A $3,000/month Meta ad spend that generates $60,000 in bookings has a 20x ROAS. A $3,000/month spend that generates $6,000 in bookings should be paused. Without attribution, both campaigns look identical: they generate leads. The founder cannot make informed budget decisions.

---

## SOLUTION: Revenue Attribution Table

### Table Name: Revenue Attribution

### Full Field Specification

| Field Name | Field Type | Source / Formula |
|---|---|---|
| Attribution_ID | Autonumber | Auto-generated by Airtable |
| Booking | Linked record (Bookings) | Set by M-BOOKING-OUTCOME-001 |
| Request | Linked record (Requests) | Set by M-BOOKING-OUTCOME-001 |
| UTM_Record | Linked record (UTMs) | Set by M-BOOKING-OUTCOME-001 |
| Campaign | Linked record (Campaigns) | Looked up from UTM_Record |
| Revenue | Currency (USD) | Lookup from Booking.Total_Value |
| Charter_Cost | Currency (USD) | Manual entry or lookup from a future Costs table |
| Gross_Margin | Formula | Revenue - Charter_Cost |
| Margin_Percent | Formula | IF(Revenue > 0, (Revenue - Charter_Cost) / Revenue * 100, 0) |
| Experience | Single line text | Lookup from Booking.Experience |
| UTM_Source | Single line text | Lookup from UTM_Record.Source |
| UTM_Medium | Single line text | Lookup from UTM_Record.Medium |
| UTM_Campaign | Single line text | Lookup from UTM_Record.Campaign |
| UTM_Content | Single line text | Lookup from UTM_Record.Content (creative ID) |
| Visitor_ID | Single line text | Lookup from UTM_Record.Visitor_ID (sss_vid) |
| First_Seen_At | Date/time | Lookup from UTM_Record.First_Seen_At |
| Booked_At | Date | Lookup from Booking.Deposit_Date |
| Days_to_Close | Formula | DATETIME_DIFF({Booked_At}, {First_Seen_At}, 'days') |
| Concierge | Linked record (Contacts) | Lookup from Request.Assigned_Concierge |
| Internal_Rating | Number | Lookup from Request.Internal_Rating |
| Notes | Long text | Manual entry for non-UTM source description |
| Created_At | Created time | Auto-generated by Airtable |

### Field Notes

Charter_Cost: This field represents the variable cost of delivering the charter: boat hire, crew, provisioning, and any experience-specific costs. Initially this is a manual entry by the operations team when the booking is confirmed. In a later phase, this can be populated from a Costs table linked to each experience.

Gross_Margin: This is the formula field that makes profitability visible. If Revenue = $14,000 and Charter_Cost = $8,500, then Gross_Margin = $5,500.

Margin_Percent: Used for experience-level and campaign-level profitability comparison. A campaign that generates high revenue but low margin is less valuable than it appears.

Days_to_Close: Critical for understanding the inquiry-to-booking conversion cycle. Fast-closing leads (3-5 days) may indicate high purchase intent. Slow-closing leads (21+ days) may indicate hesitation or price sensitivity. This field enables close-time analysis by source, experience, and concierge.

UTM_Content: This maps to the utm_content parameter in the ad URL. For Meta campaigns, this is typically the creative ID (ad name or variation). This field enables creative-level attribution, not just campaign-level.

## HOW THE LINK IS MADE

### Make Scenario: M-BOOKING-OUTCOME-001

This scenario is the single mechanism that creates the attribution link. It must execute correctly every time a Request status moves to "Booked." All revenue attribution data depends on it.

#### Trigger

Airtable: Watch Records (Requests table)
- Filter: Status field changes to "Booked"
- Fields to watch: Status

#### Module Sequence

**Module 1: Airtable - Get Record (Request)**
- Get the full Request record that triggered the scenario.
- Captures: Request ID, linked UTM record ID, Assigned Concierge, Internal Rating, Experience of Interest, Group Size, Submitted At timestamp.

**Module 2: Airtable - Search Records (UTMs table)**
- Filter: Request field = Request ID from Module 1.
- Returns: the UTM record linked to this Request.
- Captures: UTM ID, Source, Medium, Campaign, Content, Campaign record ID (if linked), First_Seen_At, Visitor_ID.

**Module 3: Router (branch on UTM found vs not found)**
- Branch A: UTM record exists. Proceed to Module 4.
- Branch B: No UTM record exists (direct or referral booking). Skip to Module 7 with Notes = "No UTM. Likely direct or referral."

**Module 4: Airtable - Search Records (Bookings table)**
- Filter: linked Request = Request ID from Module 1.
- Purpose: check if a Booking record already exists for this Request.

**Module 5: Router (branch on Booking found vs not found)**
- Branch A: Booking record exists. Use its ID in Module 6.
- Branch B: No Booking record exists. Create one in Module 5B.

**Module 5B (conditional): Airtable - Create Record (Bookings table)**
- Fields: Request (linked), Experience (from Request), Group Size (from Request), Charter Date (from Request.Preferred_Date if available), Total Value (manual, set to 0 initially, team fills in later), Deposit Date (today).
- Note: if the team creates Booking records manually before this scenario runs, Module 4 will find the existing record and Module 5B will not execute.

**Module 6: Airtable - Create Record (Revenue Attribution table)**
- Fields:
  - Booking: Booking record ID from Module 4 or 5B
  - Request: Request ID from Module 1
  - UTM_Record: UTM ID from Module 2
  - Campaign: Campaign record ID from Module 2 (if present)
  - Charter_Cost: 0 (placeholder, operations team fills in)
  - Notes: blank (auto-populated sources get no note)
- Revenue, Experience, UTM lookups, and formula fields are populated automatically by Airtable after record creation.

**Module 7: Airtable - Create Record (Audit Log table)**
- Action: "Revenue Attribution Created"
- Request ID: from Module 1
- UTM ID: from Module 2 (or "none")
- Booking ID: from Module 4 or 5B
- Timestamp: now
- Scenario: M-BOOKING-OUTCOME-001

**Module 8 (Branch B only): Airtable - Create Record (Revenue Attribution table)**
- Same as Module 6 but with no UTM_Record and no Campaign links.
- Notes: "No UTM record found. Source unknown. Manual attribution required."

#### Error Handling

If Module 2 returns no UTM record: continue via Branch B. Never halt the scenario. Attribution records with no UTM are valid data. They represent direct bookings, referrals, or cases where the UTM was not captured.

If Module 5B fails to create a Booking record: log to Audit Log and send a Slack alert to the team with the Request ID. The team can create the Booking record manually and re-trigger by setting Status back to "Contacted" then to "Booked" again.

## CAMPAIGN ROI CALCULATION

### Method

The Revenue Attribution table stores Revenue and Charter_Cost per booking. Each record links to a Campaign record. Airtable rollup fields on the Campaigns table can aggregate attribution data across all linked Revenue Attribution records.

### Rollup Fields to Add to the Campaigns Table

| Field Name | Rollup Type | Source |
|---|---|---|
| Total_Revenue_Attributed | SUM | Revenue Attribution.Revenue |
| Total_Bookings | COUNT | Revenue Attribution records |
| Average_Revenue_Per_Booking | AVG | Revenue Attribution.Revenue |
| Total_Gross_Margin | SUM | Revenue Attribution.Gross_Margin |
| Average_Margin_Percent | AVG | Revenue Attribution.Margin_Percent |
| Average_Days_to_Close | AVG | Revenue Attribution.Days_to_Close |

### ROI Formula (Campaigns Table Formula Field)

```
IF(
  {Budget} > 0,
  ROUND(({Total_Revenue_Attributed} - {Budget}) / {Budget} * 100, 1),
  0
)
```

This produces the campaign ROI as a percentage. A campaign with a $3,000 budget and $21,000 in attributed revenue has a 600% ROI.

### ROAS Formula (Campaigns Table Formula Field)

```
IF(
  {Budget} > 0,
  ROUND({Total_Revenue_Attributed} / {Budget}, 2),
  0
)
```

Return on ad spend (ROAS). A campaign with a $3,000 budget and $21,000 in attributed revenue has a 7x ROAS.

### Cost Per Booking Formula (Campaigns Table Formula Field)

```
IF(
  {Total_Bookings} > 0,
  ROUND({Budget} / {Total_Bookings}, 2),
  0
)
```

This produces the effective cost per confirmed booking from this campaign.

### How to View This in Airtable

Create a Campaigns table view named "Campaign ROI" with these fields visible: Campaign_Name, UTM_Slug, Budget, Total_Revenue_Attributed, Total_Gross_Margin, ROI_Percent, ROAS, Average_Days_to_Close, Total_Bookings. Sort by Total_Revenue_Attributed descending. This gives the founder an at-a-glance ranking of campaigns by revenue impact.

## FIRST-TOUCH ATTRIBUTION MODEL

### Why First-Touch

She Said Sail uses a first-touch attribution model. The UTM source captured on the visitor's first arrival at the site is the attributed source for any booking that follows.

This is implemented via two mechanisms:

1. sessionStorage key sss_utm: stores the UTM parameters from the current session URL. Overwritten on every new session.

2. localStorage key sss_first_touch: stores the UTM parameters from the very first session where UTMs were present. Never overwritten once set.

The UTMs table records the First_Seen_At timestamp from localStorage (the first-touch timestamp), not the sessionStorage timestamp (which could be a return visit).

### Why This Model Is Correct for She Said Sail

Luxury charter bookings are discovery-driven. A guest discovers She Said Sail through a Meta reel or an Instagram ad, gets excited, saves the link, and returns directly (no UTM) 3 days later to submit a booking inquiry. Under last-touch attribution, this booking would be attributed to "direct," making the Meta ad appear worthless. Under first-touch attribution, it is correctly attributed to the Meta campaign that created the desire.

For a service where the first impression drives the eventual decision, first-touch is the right model.

### Limitation

First-touch attribution cannot track a scenario where a guest discovers She Said Sail through organic search, forgets about it for two months, sees a Meta retargeting ad, and then books. In that case, the organic search gets full credit under first-touch, even though the retargeting ad was the decision trigger.

This limitation is acceptable for the current stage of She Said Sail's marketing sophistication. A multi-touch attribution model requires a more complex data infrastructure and is not recommended until the attribution chain described in this document is working reliably.

## WHAT CANNOT BE ATTRIBUTED

The following bookings will not have a UTM chain and cannot be attributed to a paid campaign or organic source through the standard system:

### Word-of-Mouth Referrals

Source = "direct", no UTM parameters. Guest heard about She Said Sail from a friend and navigated directly to the site. The Revenue Attribution record will have no Campaign link. These bookings are extremely valuable and should be tracked manually.

Recommended practice: when the concierge speaks with the guest and learns it was a referral, add a note to the Revenue Attribution record: "Source: referral from [contact name if known]." The Notes field exists for this purpose.

### Organic Social Discovery

Source = "instagram", medium = "organic" or absent. Guest discovered She Said Sail on Instagram without clicking a tracked ad link. This may appear with utm_source=instagram if the guest used the link in bio, or it may appear as direct if they typed the URL.

Recommended practice: add "Source: Instagram organic" to the Revenue Attribution notes field.

### Friend Referrals from Existing Clients

An existing client recommends She Said Sail to a friend. The friend arrives directly with no UTM and no referral parameter. This is one of the most valuable customer acquisition channels and is completely invisible to the UTM system.

Recommended practice: add a Referral_Source field to the Requests table (single line text). When the concierge identifies a referral during initial contact, they enter the referring client's name. This creates a manual referral tracking layer that runs alongside the UTM system.

### Tracking Summary for Non-Attributed Bookings

All non-attributed bookings should still have Revenue Attribution records created by M-BOOKING-OUTCOME-001. The records will have blank UTM and Campaign links. The Notes field and the Requests.Referral_Source field (if added) provide the manual tracking layer. Over time, this data reveals the true mix of acquisition channels including the channels that UTM tracking misses entirely.

```
*She Said Sail | Weekly Revenue Report*
*Week: [Mon DD MMM] to [Sun DD MMM YYYY]*

---

*REVENUE*
Total revenue booked this week: $[X,XXX]
Number of bookings confirmed: [X]
Average booking value: $[X,XXX]
Total gross margin: $[X,XXX] ([XX]%)

*TOP SOURCES*
1. [utm_source]: $[X,XXX] ([X] bookings)
2. [utm_source]: $[X,XXX] ([X] bookings)
3. Direct / unattributed: $[X,XXX] ([X] bookings)

*TOP CAMPAIGN*
[utm_campaign_slug]: $[X,XXX] revenue, [X] bookings, [XXX]% ROI vs budget

*TOP EXPERIENCE (by revenue)*
[Experience Name]: $[X,XXX] ([X] bookings, [XX]% margin)

*CLOSE SPEED*
Average days from inquiry to booking: [X] days
```
